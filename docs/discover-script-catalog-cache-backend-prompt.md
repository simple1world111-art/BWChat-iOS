# 发现页剧本目录缓存：后端调整 Prompt

请调整 BWChat 后端的剧本目录接口，使 iOS 端的持久化缓存、分类切换、分页和强制刷新具有稳定且可验证的一致性。客户端已经完成缓存优先策略，因此以下后端调整属于推荐优化，不是本次客户端缓存生效的硬依赖。

## 当前接口

- `GET /scripts/categories`
- `GET /scripts?scope=public|mine&category_id=<可选>&cursor=<可选>&limit=1...50`

## 必须保证的响应契约

1. `GET /scripts` 返回统一结构：

```json
{
  "data": {
    "scripts": [],
    "has_more": false,
    "next_cursor": null
  }
}
```

2. 每个剧本必须返回稳定且完整的目录字段，至少包括：`script_id`、`title`、`synopsis`、`cover_url`、`category_ids`、`visibility`、`status`、`creator`、`roles`、`is_admin_hidden`、`created_at`、`updated_at`。同一条数据不要在不同请求中混用占位封面与真实封面。
3. `scope=public` 只能返回当前用户有权看到的公开、可用、未被管理员隐藏的剧本；严禁泄漏草稿、私有或已归档内容。
4. `scope=mine` 只能返回当前登录用户自己的剧本。即使查询参数被篡改，也不能返回其他用户的私有数据。
5. 分页必须使用稳定排序，例如 `updated_at DESC, script_id DESC`，游标同时编码排序值和唯一 ID；同一数据版本下连续翻页不得重复或遗漏。`has_more=false` 时 `next_cursor` 必须为 `null`。
6. `category_id` 不存在或用户无权访问时返回明确的 4xx 业务错误，不要静默退回全部分类。

## 缓存与条件请求

1. 为分类和剧本首屏响应提供稳定的 `ETag`，并支持 `If-None-Match`；内容未变化时返回 `304` 且无响应体。
2. ETag 必须基于用户最终可见的数据版本计算，不能包含请求时间、trace ID 等每次变化的字段。
3. `scope=mine` 使用 `Cache-Control: private, no-cache`（允许客户端存储，但每次条件校验）；禁止 CDN 共享缓存。
4. `scope=public` 可以使用短时共享缓存，但若结果受登录态、地区、语言、审核分层影响，必须使用正确的 `Vary` 或把这些维度纳入缓存键，避免串数据。
5. 分类新增、删除、改名、排序变化，以及剧本创建、更新、删除、上下架、公开性变更、管理员隐藏、分类变更、封面或角色资料变更后，必须推进对应资源版本并使 ETag 变化。
6. 建议在响应中增加单调变化的 `revision` 或可靠的 `updated_at`，便于日志定位缓存一致性问题；不要用客户端时间参与版本判断。

> 注意：当前 iOS 端已使用本地 TTL、账号隔离和强制刷新，但尚未发送 `If-None-Match`。后端可先兼容 ETag；客户端后续接入条件请求后即可直接减少响应体和流量。

## 并发与失效场景

- 当用户正在翻页时某剧本被删除或改为私有，后续游标请求不得泄漏该条数据，也不能导致整页重复。
- 更新接口成功返回前，应完成读模型/缓存版本失效；避免客户端强制刷新仍拿到旧目录。
- 如果采用异步读模型，写接口响应中返回 `revision`，并保证按该 revision 查询时可读到新数据，或明确返回可重试状态。
- 用户退出登录或切换账号时，服务端不能依赖客户端缓存清理来保证隔离。

## 验收测试

请补充自动化测试覆盖：

1. 相同身份、查询和数据版本连续请求得到相同 ETag，第二次携带 `If-None-Match` 返回 304。
2. 新建、编辑、删除、上下架、修改分类或封面后，相关 public/mine/category 查询的 ETag 均发生变化并返回新内容。
3. public、用户 A 的 mine、用户 B 的 mine 三类缓存结果完全隔离。
4. 两页以上游标分页无重复、无遗漏，边界时间相同的多条数据仍保持稳定顺序。
5. 未登录访问、越权 category、私有/草稿/管理员隐藏数据均符合权限预期。
6. 老版本客户端不发送 `If-None-Match` 时仍能正常获得完整 200 响应，字段结构保持向后兼容。

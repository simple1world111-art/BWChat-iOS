# 删除收藏功能：后端实施 Prompt

你正在维护 BWChat 后端。请完整删除“收藏”能力，包括聊天消息收藏与短剧收藏，但必须保留普通消息转发、消息多选、本地删除、短剧点赞、评论、关注和播放等相邻能力。

## 工作方式

1. 先扫描仓库并列出收藏功能的真实依赖链：路由、Controller/Handler、Service、Repository/DAO、DTO/Schema、数据库迁移、缓存、搜索索引、队列任务、WebSocket/Outbox 事件、远程配置、权限、监控、测试和文档。不要根据本 Prompt 猜测文件名或技术栈。
2. 给出删除清单和风险点后直接实施，不要只隐藏入口或只关闭 feature flag。
3. 只删除收藏专属逻辑。共享的消息读取、媒体授权、消息转发、短剧查询和互动基础设施必须保留。
4. 所有改动应通过现有格式化、静态检查、单元测试、集成测试和数据库迁移检查。

## 必须移除的 HTTP 能力

聊天收藏：

- `POST /chat/favorites`
- `GET /chat/favorites`
- `GET /chat/favorites/{favorite_id}`
- `DELETE /chat/favorites/{favorite_id}`
- `POST /chat/favorites/{favorite_id}/forward`

短剧收藏：

- `POST /short-drama/videos/{video_id}/favorite`
- `DELETE /short-drama/videos/{video_id}/favorite`

同时删除这些端点对应的请求/响应 DTO、鉴权分支、幂等键用途、OpenAPI 定义、SDK 生成入口、限流规则和接口测试。不要删除普通消息转发接口或转发 bundle 能力。

## 必须移除的数据契约

从短剧列表、详情、播放 feed 和互动响应中删除收藏专属字段及其兼容别名，包括实际代码中存在的：

- `favorite_count`
- `favorites_count`
- `collect_count`
- `favorited_by_me`
- `collected_by_me`
- `favorite`、`favorited`、`collected`

删除聊天收藏实体及分页契约，包括 `FavoriteItem`、`FavoritePage`、收藏内容类型、创建请求和“从收藏转发”请求。检查 GraphQL、RPC、WebSocket payload 或内部 DTO 是否还有同义字段。

## 持久化与异步链路

- 删除仅服务于收藏的表、关联表、列、索引、外键、触发器、存储过程、物化视图和搜索索引。重点核查 `favorites`、`favorite_items` 以及短剧收藏关系/计数列，但以仓库真实 schema 为准。
- 删除收藏专属缓存 key/namespace、缓存失效逻辑和预热任务。
- 删除 `favorite.created`、`favorite.deleted` 及其他收藏专属 Outbox/WebSocket/消息队列事件、消费者、重试任务和死信处理。
- 删除收藏专属媒体引用后，必须使用现有引用计数或归属检查；不得误删仍被原消息、转发消息或短剧使用的媒体。
- 清理收藏专属幂等记录时，不得影响普通消息转发或其他业务使用的通用幂等表。
- 删除 `message_favorite_v1` 等收藏专属 feature flag、动态个人中心菜单项、配置校验和默认配置。若配置由独立配置中心维护，请同时给出需要执行的外部配置变更清单。

## 数据库迁移要求

采用分阶段、安全退场：

1. 第一阶段停止新建收藏并停止业务读取，部署后确认新 iOS 客户端已无收藏请求。
2. 对仍在使用旧版本的客户端，收藏端点在约定兼容窗口内返回项目标准 envelope 的明确 `410 Gone / FEATURE_REMOVED`，禁止返回假成功、空收藏或无限重试型错误。若项目网关不支持 410，请使用现有等价的“功能已移除”错误码并记录原因。
3. 观察访问日志和队列积压，确认兼容窗口结束且无有效旧流量后，再移除退场路由。
4. schema 删除使用独立迁移；先备份或按项目数据保留策略归档，再删除数据结构。迁移必须明确 forward 与 rollback 策略，禁止在应用启动时临时执行 DDL。
5. 若业务明确要求立即物理删除用户收藏数据，使用可审计、可分批、可重试的清理任务，并输出删除量、失败量和校验结果。

## 需要保留的能力

- 普通单条/逐条/合并消息转发及其 bundle 详情。
- 原消息和转发消息的媒体授权、消息历史与撤回语义。
- 聊天消息复制、引用、保存到系统相册、多选和本地删除。
- 短剧点赞、评论、关注、播放进度、解锁和发布流程。
- 与收藏共享的通用缓存、Outbox、鉴权、分页和幂等基础设施。

## 测试与验收

至少补齐或更新以下验证：

- 路由表、OpenAPI 和生成 SDK 中不存在收藏接口。
- 后端源码（排除历史迁移归档与本次说明）中不存在收藏 Controller、Service、Repository、DTO、事件消费者或 feature flag 引用。
- 短剧响应不再输出收藏状态和计数；点赞、评论、关注仍正常。
- 普通消息转发的单条、逐条和合并模式仍正常，且不依赖收藏 DTO。
- 旧客户端访问退场端点时得到稳定、不可重试的“功能已移除”响应，并有版本、用户和端点维度的监控。
- 数据迁移前后校验收藏专属记录数、孤儿媒体引用、外键完整性和队列积压。
- 全量测试通过；若存在无法运行的测试，说明原因、影响范围和替代验证证据。

## 最终交付格式

请输出：

1. 删除/修改的文件与职责摘要。
2. 已删除的接口、字段、事件、配置和数据结构清单。
3. 数据迁移与旧客户端兼容方案。
4. 实际执行的测试命令和结果。
5. 尚需人工或外部系统执行的操作，以及可观测指标和回滚条件。

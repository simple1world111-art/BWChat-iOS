# 后端任务 Prompt：将用户侧“猫粮”统一更名为“猫币”

请在 BWChat 后端、运营后台、远程配置、推送、H5 和服务端生成文案中完成一次**纯展示品牌改名**：把面向用户的“猫粮”统一改为“猫币”。此次改名不得改变余额数值、账本语义、兑换比例、计费规则、支付商品或历史交易结果。

## 必须修改的用户可见内容

全面搜索并修改所有可能展示给用户的旧称，包括但不限于：

1. `GET /api/v1/app/config` 及其他远程配置中的 `title_i18n`、说明、活动标题、钱包配置、广告奖励文案和审核模式文案。
2. 钱包余额、充值、提现、交易流水、礼物、广告奖励、红包、转账、动态付费解锁、短剧付费解锁、语音/视频计费相关的错误提示与成功提示。
3. WebSocket 事件、系统消息、聊天回执、推送通知标题/正文、邮件或站内信中由服务端拼接的货币名称。
4. H5 游戏、活动页、帮助中心、服务条款、运营后台和 CMS 模板中的展示名称。
5. 服务端返回的可展示 `message`、`description`、`subtitle` 等字段；稳定错误码保持不变，只替换本地化展示文案。
6. 新生成的交易描述和账单摘要。历史账本数据不得重算；如果历史记录保存的是可展示快照，可在读取层映射旧称为新称，或做可回滚的数据迁移。

## 协议兼容要求（重要）

当前 iOS 客户端继续使用以下既有机器字段和稳定值。**本次不要删除、直接重命名或改变语义**：

- `cat_food`
- `cat_food_amount`
- `cat_food_balance`
- `cat_food_delta`
- `cat_food_products`
- `charged_cat_food`
- `earned_cat_food`
- `unlock_price_cat_food`
- `unlockPriceCatFood`
- `currency: "cat_food"`
- `insufficient_withdrawable_cat_food_balance`
- StoreKit 商品 ID：`com.bwchat.app.catfood.*`

这些名称属于客户端协议、数据库/账本或已发布的 StoreKit 商品标识，不是用户展示文案。仅为品牌改名，无需修改它们。这样旧客户端、新客户端、历史订单、余额缓存和支付回执可以继续兼容。

如果业务坚持将机器字段也改为 `cat_coin*`，必须采用增量兼容方案：

1. 新增 `cat_coin*` 别名，不删除旧字段；请求同时接受新旧字段，响应在迁移期至少保留旧字段。
2. 数据库先新增别名列/视图或在服务层映射，禁止直接破坏性改列；账本保持同一资产与同一余额来源。
3. WebSocket、推送 payload 和 REST API 同时兼容至少两个已发布客户端版本，并通过版本/能力协商逐步切换。
4. StoreKit 商品 ID 永久保持原值，除非另行创建并审核新商品；不得因展示改名使旧交易无法验证或补单。
5. 错误码保持稳定；如新增 `insufficient_withdrawable_cat_coin_balance`，服务端仍需兼容旧错误码，客户端升级完成前不要移除。
6. 提供灰度、监控、回滚和迁移完成条件，并单独安排客户端支持新字段后再讨论下线旧字段。
